Workflow

Use the agent as a funding operations layer.

The agent should make the work easier to see and prepare, while humans stay responsible for final facts, judgment, and transmission.

Good uses

  • Summarize current funding status and queue priority.
  • Compare grant fit, deadline, eligibility, and likely ask size.
  • Draft Slack-ready updates, LOIs, narratives, and checklist packets.
  • Identify missing BOT facts before a human starts submission.

Approval-gated uses

  • Posting to Slack or tagging reviewers.
  • Uploading, moving, or sharing Drive files.
  • Logging into portals or changing account data.
  • Emailing, contacting funders, or submitting applications.

Team roles

  • Josh owns approval, routing, and final go/no-go calls.
  • Safia reviews, modifies, and submits approved materials.
  • The agent validates, drafts, summarizes, and flags blockers.

Prompt set

Start with precise Slack calls.

Keep prompts short, bounded, and explicit about whether the agent should draft locally or request approval to send.

@money status: open, watching, upcoming, follow-up only. Do not post outside this thread.
@money review the current queue and rank the next three draft targets by deadline and fit.
@money draft a Safia review packet for the top opportunity. Include blockers and required BOT facts.
@money prepare an aggregated Slack update for Safia, but do not send until Josh approves exact wording.
@money list what is blocked by eligibility, portal readiness, documents, or human approval.

Teaching run of show

45-minute session script.

This is built for a live Slack demo with funding work that stays inside BOT Funding boundaries.

Set the guardrail

Explain the approval rule and show examples of allowed drafting versus gated sending.

Call status

Ask for a concise queue summary with open, watching, upcoming, and follow-up-only sections.

Pick one target

Use deadline, eligibility, BOT fit, and missing documents to choose the next drafting target.

Draft locally

Create a Slack-ready review packet, LOI outline, or narrative draft without transmitting it.

Review as humans

Have Safia or the team modify facts, ask size, framing, attachments, and final submission plan.

Approve exact action

If anything must be sent, posted, uploaded, or submitted, require exact final approval first.

Queue language

Teach the buckets, not just the grants.

These labels keep the team from confusing a promising opportunity with one that is ready to submit.

Bucket Meaning Current examples
Draft-ready after validation Strong fit, live path, and useful deadline, but final facts still need human confirmation. Bank of America RFP, Neighborhood Builders, Edyth Bush, First Horizon, Parikh, Pabst, Truist, Walmart Spark Good.
Watch / recheck Potential fit, but one or more path, county, eligibility, or timing details need revalidation. Duke Energy Foundation Florida; invitation-only or not-yet-open funders.
Follow-up only Already acted on or no current drafting need; track only for response or next status. AWS Imagine Grant follow-up tracking.
Provider infrastructure Useful for reimbursement or operating capacity, not a quick-grant draft candidate. CareerSource ETPL.
Stop gate Transmission, portal, Drive, outreach, payment, or submission action requiring exact approval. Slack post, funder email, portal login, document upload, application submit.

Standard handoff

End every agent response with action clarity.

Good final shape

  • What changed or what was found.
  • What is ready for human review.
  • What is blocked and who owns the unblock.
  • What exact approval is needed before any outbound action.

Do not normalize

  • Always-on posting without a current approval.
  • Portal work from stale facts.
  • Moving files as a substitute for review.
  • Calling a queue item submitted unless it is verified.
